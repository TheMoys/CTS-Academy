# Fase 02: Análisis — CTS Academy & Evaluator

Bienvenido a la **Fase 02: Análisis** de **CTS Academy & Evaluator** bajo la metodología RUP (Rational Unified Process).

---

## 🎯 Propósito del Modelo de Análisis

El modelo de análisis actúa como el puente formal entre la especificación de requisitos del usuario y el diseño arquitectónico concreto. Su propósito es definir **cómo** el sistema responderá a las necesidades del negocio abstrayéndose de tecnologías particulares (bases de datos relacionales, frameworks web, protocolos de red).

En esta fase se formalizan:
1. **Clases de Análisis (Estereotipos RUP / BCE)**:
   * **Boundary (`<<boundary>>` / Frontera)**: Mediatizan la comunicación entre los actores externos y el interior del sistema.
   * **Control (`<<control>>` / Control)**: Encapsulan la lógica de coordinación, flujo de negocio y transacciones de cada caso de uso.
   * **Entity (`<<entity>>` / Entidad)**: Representan la información y el comportamiento duradero del dominio.
2. **Realizaciones de Casos de Uso (Análisis)**:
   * Diagramas de comunicación y colaboraciones preliminares que demuestran cómo interactúan las clases BCE para dar cumplimiento a cada uno de los 35 casos de uso especificados en la Fase 01.
